# 社會計量站位辨識

高中表演藝術課用的即時站位圖表工具。教師用廣角 webcam 從教室高處斜拍全班（最多約 42 人），學生用**身體站位**回答問題，程式把站位轉成圖表投影出來，讓「看不見的立場」變成「看得見的分布」。

純前端、不需後端；**影像只在這台電腦的瀏覽器內處理，不上傳、不存檔**。畫面與圖表只用圓點代表人，不顯示人臉。

## 核心：三種社會計量技術（各是一個獨立模式）

| 技術 | 學生怎麼站 | 你要設定 | 輸出圖表 |
|---|---|---|---|
| **光譜 Human Spectrum** | 一條線，兩端是極端立場，依程度站在線上 | 方向（左→右／遠→近）、格數 3/5/7/11、兩端文字 | 長條圖（綠→紅漸層） |
| **矩陣 Locograms** | 空間分成區域，每區是一個選項 | 欄×列（最多 4×3）、各區名稱 | 方塊圖（人數＋顏色深淺，最多的一格框起） |
| **關係距離 Distance Metric** | 以某人／主題為圓心，依心理距離站遠近 | 在畫面上點出圓心、圈數 2–5、每圈寬度（公尺）、各圈名稱 | 同心圓（每圈人數＋圓點實際分布） |

另有「色卡（輔助）」：學生舉**紅／黃／藍／綠／白**五色卡選擇，每色可自訂代表的選項，作為輔助，不是主要辨識方式。白色沒有色相，只能靠「低飽和＋高亮度」，白牆、白衣、日光燈都容易誤判——**用白卡一定要先拍背景基準並取樣**，且仍建議手動核對。

每種技術都有：右側設定面板、**疊在影像上的輔助線**（分格線／區域框＋名稱／同心圓，已依校準換算透視）、投影圖表。

## 開啟方式

1. **最簡單**：用 Chrome 或 Edge 開啟 `index.html`（雙擊或拖進瀏覽器）。
2. **較穩定（建議）**：雙擊 `啟動.command`（Mac）或 `啟動.bat`（Windows，需裝 Python）。它只在本機 `http://localhost:8000` 提供頁面（不對外），好處是鏡頭權限與題組暫存較穩定、離線模式也需要它。

第一次掃描時會下載偵測模型（YOLOv10s，約 29 MB，來自 Hugging Face；onnxruntime-web 1.20.1 來自 jsDelivr），之後瀏覽器會快取。**教室沒有網路時請見下方「離線使用」，上課前先準備好。**

## 上課流程（五步）

1. **開鏡頭**（或「載入照片測試」）。
2. **① 校準地板**：依序點地板四角——左上(遠左)、右上(遠右)、右下(近右)、左下(近左)。點完後可拖曳角點微調；在偵測設定填入地板實際寬×深（公尺，預設 8×6，「關係距離」的圈寬用公尺換算，要填接近實際的數字）。同一個鏡頭位置只需校準一次，會自動記住（換位置或碰到鏡頭就要重點）。
3. **選題**：左側題目清單點選（或 ← → 鍵）。內建教案範例題組：
   - 光譜「你現在住的地方，舒適嗎？」（非常舒適→非常不舒適）
   - 矩陣「你通常怎麼來上學？」（捷運／公車／走路／家長接送／腳踏車／其他）
   - 關係距離「你覺得自己離『買得起房』有多近？」（圓心＝房子；先按「在畫面上點選圓心」，點在地上放房子標誌的位置）
   可新增／複製／刪除／排序題目、改題目文字與技術、匯出匯入題組(JSON)。
4. **② 掃描一次**（或「連續掃描」）。連續掃描會取最近 N 張影格（預設 5）把位置接近的點歸群、只留過半影格都出現的點、位置取中位數，讓人數不閃動。
5. **③ 手動校正 → ④ 鎖定本題 → 下一題**：
   - 點空白處＝新增、點圓點＝刪除、拖曳圓點＝移動；`Ctrl+Z` 復原。紅點＝自動偵測，藍點＝手動。
   - 畫面同時顯示「自動偵測 N／手動新增 +a／手動刪除 −d」，總人數＝偵測＋新增（被你刪除的點，重新掃描時不會回來）。
   - 「鎖定」會凍結本題結果並自動存一筆快照；鎖定後不能再掃描或編輯，要改請先解除。「存快照」可在未鎖定時隨時記錄。
   - 「匯出 CSV」＝所有題目的所有快照（UTF-8 含 BOM，Excel 直接開啟不亂碼）。

快速鍵：`S` 掃描、`E` 手動校正、`L` 鎖定、`P` 投影視窗、`← →` 換題、`1`–`9` 換組、`A` 全班同場、`M` 合併檢視、`Ctrl+Z` 復原。

## 建議流程：先設題，最後再校準一次

1. **不用鏡頭就能先把題目全部設好**：每班的題組、各題的技術與選項、關係距離的圓心（可直接輸入「x、y 公尺」，地板左上角為 0,0）。
2. **之後再來一次校準**：開鏡頭（人不用在場，只要看得到地板四角）→「① 校準地板」→ 填地板實際寬×深。
3. **這次校準就適用該班的所有組別、所有題目**：校準存在「班級」底下（比例座標），不是存在某一題或某一組。圓點存的是畫面座標、圓心存的是公尺，所以事後才校準或重新校準，之前掃描的結果都會依新校準重新計算，不用重做。
4. **同一間教室、同一個鏡頭位置**：按「校準套用到全部班級」（需教師登入），或先校準好一班再新增班級——新班級會自動沿用目前班級的校準。
5. 只有鏡頭被移動、換教室、或換成不同長寬比的畫面（例如 4:3 換 16:9）才需要重新校準；同長寬比、不同解析度會自動換算。

## 班級與組別（多班、分組存檔）

- **班級**：頁首第二列選單切換。每班各自存：題目清單（30 題以上沒問題）、每題每組的結果與快照、地板校準四角、地板實際大小。可一次新增多班（輸入 `701,702,703`），也能改名、刪除。
- **範本題組**：把某班的題目「存為範本」，之後新增班級會自動套用；「套用範本」可重設本班題目（會清掉本班結果）。
- **組別**（預設 4 組，可改 1–8）：每題的結果依組別分開存。
  - **輪流上場**：選「第 N 組」，那組站完就掃描、鎖定；換下一組（快速鍵 `1`–`9`）。
  - **全班同場**（`A`）：全班一次站完，結果存在「全班同場」。**注意：同場時程式不會自動分辨誰屬於哪一組**（影像看不出組別），只統計整體。
  - **合併檢視**（`M`）：把第 1–N 組的圓點相加看全班分布，**唯讀**；可存快照。
- 題目清單可搜尋（題目文字或題號），每題旁的小方塊顯示各組完成度（綠＝已鎖定、橘＝有資料、灰＝空）。
- 切換班級、組別、題目都會自動存檔，換班時自動套用該班的校準。

### 資料存在哪、怎麼備份

- 存在**這台電腦這個瀏覽器**的 IndexedDB（容量大；實測 18 班 × 33 題 × 5 組、每格 40 點約 7 MB，存取只要幾十毫秒）。只存題目、設定、圓點座標、快照，**不存影像**。
- 資料綁定「瀏覽器＋網址」：用 `localhost`、GitHub Pages 網址、雙擊 `index.html` 開，是**三個互相看不到的儲存空間**。請固定用同一個入口。清除瀏覽器網站資料會一併清掉。
- **每週備份**：按「全部備份」存成 JSON（含所有班級與範本），單班用「匯出本班」；「匯入備份」可還原或搬到別台電腦。CSV 有「班級」「組別」欄位，可匯出本班或全部班級。
- 預設沒有雲端同步；要讓老師與學生裝置共用資料，請見下方「雲端同步（Firebase）」。

## 雲端同步（Firebase）：老師與學生裝置共用同一份資料

> 目前已設定並啟用（專案 performingarts-adb73；規則已發布）。以下設定步驟供換專案時參考。

沒有設定時，每個人的班級資料只存在自己的瀏覽器（互不相通）。設定 Firebase 後：班級、題目、各組圓點與快照會即時同步到所有開啟網站的裝置。

**權限（由 Firestore 規則在伺服器端執行，不是前端把關）**
- **學生（不用登入）**：可以看到所有班級與題目，可以掃描、校正圓點、鎖定、存快照（只會寫入「各組結果」）；**不能**新增／改名／刪除班級、改題目與校準。
- **教師（Google 登入且在名單內）**：全部權限，包含校準套用全部班級、匯入、套用範本。
- ⚠ 學生不用登入＝**任何知道網址與 Firebase 設定的人都能寫入各組結果**（但不能改題目與班級）。這是「不用登入」的代價；若班級資料被亂改，可從「全部備份」還原。

**設定步驟（一次性，約 15 分鐘；需要你自己的 Google 帳號）**
1. [Firebase 主控台](https://console.firebase.google.com/) → 新增專案（可關閉 Google Analytics）。
2. 建置 → **Firestore Database** → 建立資料庫（選離你近的區域，例如 asia-east1，先用「正式版模式」）。
3. 建置 → **Authentication** → 開始使用 → 登入方式 → 啟用 **Google**（填支援 email）。再到「設定 → 已授權的網域」加入 `bo09327405.github.io`（`localhost` 預設已有）。
4. Firestore → **規則**：貼上本專案的 `firestore.rules`，把 `TEACHER_EMAIL_1`、`TEACHER_EMAIL_2` 換成教師 email，按發布。
5. 專案設定 → 一般 → 「您的應用程式」→ 新增網頁應用程式 → 複製 `firebaseConfig`（apiKey、authDomain、projectId、appId），貼到 `js/config.js` 的 `firebase`，commit 並推送。這些值是公開的網頁設定，不是密鑰。
6. 打開網站 → 按「教師登入（Google）」→ 若班級是本機建的，按「上傳本機班級到雲端」。之後學生開網址就會看到同樣的班級。

**行為與限制**
- 以雲端為準：學生裝置上舊的本機班級不會顯示；題目與設定永遠以雲端（教師）為準。
- 衝突處理：不同裝置同時編輯**不同組**不會互相覆蓋（逐組更新）；同一組同時編輯以「最後寫入」為準。
- 需要網路：離線時修改只存在本機快取，**不會**在連線後自動補送，請在有網路時操作。
- 免費額度（Firestore Spark 方案）對一個學校的使用量通常足夠，但請自行確認用量與收費條款。
- 資料內容：班級名稱、題目、圓點座標、人數、快照；**不含姓名、座號、影像**。仍屬學生相關資料，請先確認學校同意。
- 隱私與 Google：啟用後，所有使用者的瀏覽器會連到 Google/Firebase 伺服器；學生未登入時使用匿名連線（不收集帳號）。

## Google 登入（只有老師能管理班級）：僅本機模式

- 啟用後，**只有教師名單內的 Google 帳號**能：新增／改名／刪除班級、匯入備份、套用範本、還原範例題組、匯入題組。掃描、校正、鎖定、出圖、匯出等上課操作**不受限制**（沒登入也能上課）。
- ⚠ **這是介面層的把關，不是資安機制。** 程式和資料都在使用者自己的瀏覽器裡，會用開發者工具的人可以繞過。它的用途是防學生誤觸或在老師電腦上亂改，不是防駭。要真正的權限控管需要後端（見下）。
- 教師名單：預設留空，**這台電腦上第一個成功登入的 Google 帳號自動成為管理者**（所以請你自己先登入），之後按「教師名單」新增其他老師的 email。名單存在這台電腦的瀏覽器裡，不會出現在公開 repo。也可以把 email 寫進 `js/config.js` 的 `teachers`（但會公開在 repo）。
- **學生端完全不用登入**：掃描、校正、鎖定、出圖、匯出、投影視窗都不需要登入；只有按下「教師登入（Google）」才會載入 Google 的程式，學生使用時不會連到 Google。
- 目前部署的教師：2 個帳號，以 SHA-256 雜湊寫在 `js/config.js`（公開 repo 看不到明文 email；雜湊仍可被猜 email 反推，不是機密）。
- 沒填 Client ID 時，登入功能**不啟用**（所有人都能管理），頁首會顯示「Google 登入未啟用」。

### 設定步驟（一次性，約 10 分鐘）

1. 開 [Google Cloud Console](https://console.cloud.google.com/) → 建立專案。
2. 「API 和服務」→「OAuth 同意畫面」：使用者類型選「外部」，填應用程式名稱與你的 email；測試階段把老師的 Google 帳號加進「測試使用者」（或之後「發布應用程式」）。
3. 「憑證」→「建立憑證」→「OAuth 用戶端 ID」→ 類型選「**網頁應用程式**」。
4. 「已授權的 JavaScript 來源」加入：`https://bo09327405.github.io`（以及本機測試用的 `http://localhost:8000`）。不需要填重新導向 URI。
5. （已完成）複製產生的 **用戶端 ID**（`xxxx.apps.googleusercontent.com`），貼到 `js/config.js` 的 `googleClientId`，commit 並推送。用戶端 ID 是公開資訊，不是密鑰，可以放在公開 repo。
6. 打開網站，按右上角「Google 登入」；登入的第一個帳號成為管理者。

注意：Google 登入不能在雙擊開啟（`file://`）的頁面使用，請用 GitHub Pages 網址或 `啟動` 腳本（localhost）。登入狀態只保留在該分頁，關閉分頁或憑證過期（約 1 小時）就要重新登入；未登入不影響上課。

## 發布到 GitHub（公開 repo）注意

- repo 只放程式碼與文件。`.gitignore` 已排除備份 JSON、CSV、照片與模型檔。**請勿把班級備份、CSV、含學生的照片或影片 commit 到公開 repo**。
- 可用 **GitHub Pages** 發布（Settings → Pages → Deploy from branch → `main` / root）。網址是 https，鏡頭權限最穩；頁面本身仍是純前端，影像不會傳到 GitHub。
- 授權：本專案程式碼為 MIT（見 `LICENSE`）；YOLOv10 權重為 AGPL-3.0，**repo 不含權重**，由使用者瀏覽器自 Hugging Face 下載或用 `tools/offline_setup.py` 取得。

## 投影視窗

按「投影視窗」會開新視窗（網址 `index.html#view`）：深色底、只顯示題目與圖表、字很大。把它拖到投影幕那個螢幕，在視窗裡**雙擊（或按 F）全螢幕**。主視窗任何更動即時同步。若瀏覽器擋彈出視窗請允許。

## 攝影機擺放建議

- 架在教室**後方或側後方的高處**（講桌對面的牆上、櫃子頂、腳架拉高），**往下斜拍**，越高越好——高角度能減少前排擋後排、腳點也比較準。
- 整片站位地板都要入鏡，四個角最好都看得到（校準要點）。站位區不要太貼近鏡頭（太近時人比分塊大，偵測會切壞人）。
- 光線均勻、不要逆光；地板上用膠帶貼出光譜線、矩陣分區或圓心會讓學生更容易站準（程式的格線只是依校準換算，學生看不到）。
- 1080p 即可；webcam 若可選 1920×1080 請選。盡量固定不動。
- 建議學生**間隔一點**、不要疊在一起；請學生站好不動 2–3 秒再掃描。

## 偵測方式與設定（進階）

- 預設模型：**YOLOv10s**（ONNX Runtime Web，優先 WebGPU，退回 WASM）。另有 YOLOv10n（較快）、COCO-SSD（舊版，比較不準，只當對照）。YOLO 權重授權為 AGPL-3.0（Ultralytics），自行轉載或商用請留意。
- 分塊：把「地板＋上方站立人影範圍」切成有重疊的橫向分塊（自動），每塊各自偵測，丟掉貼著內側邊界被切斷的框，再用 NMS 合併（IoU 與包含關係）。
- 腳點：預設取偵測框底部中點；「遮擋補償（實驗）」在框高/框寬偏小時往下補，**尚未用真實站位驗證，預設關閉**。
- 沒有 WebGPU 的電腦會退回 WASM，約慢 10–30 倍（見「驗證報告」），此時預設改 YOLOv10n，並請用「掃描一次」。

## 離線使用

1. 有網路時執行一次：`python3 tools/offline_setup.py`（只抓小模型加 `--small`）。它會把 onnxruntime-web、`ort-wasm` 與 `.onnx` 模型下載到 `vendor/`、`models/`。
2. 之後用 `啟動.command`／`啟動.bat` 開啟（離線的 WASM 必須透過 `http://localhost`，不能雙擊 index.html）。
3. 若只有模型檔：在「偵測設定」按「選擇本機模型檔 (.onnx)」手動選。

## 隱私

影像只在瀏覽器記憶體中處理，程式沒有任何上傳或存檔影像的程式碼；唯一的網路請求是下載程式庫與模型（jsDelivr、Hugging Face），不含你的資料。班級、題目、校準點、圓點位置與快照存在瀏覽器的 IndexedDB（只在這台電腦），不含影像、不含姓名或座號。測試用的課堂照片含學生臉部，請勿放進這個資料夾或上傳。

## 限制與誤差說明（請誠實看待這個工具）

- **一定會有漏抓與誤抓**，尤其後排被擋住、緊貼站位的學生。用一張課堂照片（約 28 人可見，低角度）實測，召回率約 60%、精確度很高；詳見 `驗證報告.md`。所以流程設計成「掃描 → 看數字 → 手動校正 → 鎖定」，**投影前請先目視核對人數**。
- 位置誤差來自：地板四角點得準不準、鏡頭是否被移動、腳被遮住時腳點偏高（會讓人看起來離鏡頭更遠）、地板實際寬深填得準不準（影響關係距離公尺換算）。
- 站在邊界線上的人，歸屬哪一格可能判斷不同；請學生站在格內。
- 光譜／矩陣的格線是由四角點用平面透視換算，假設地板是平的矩形。
- 色卡模式必須先拍「背景基準」（五色中白色最容易誤判）（木地板與淺藍制服會造成大量誤判）。
- 本工具是教學輔助，不是精密量測，也不適合拿來評分個別學生。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 鏡頭打不開 | 看瀏覽器網址列的相機圖示，允許使用；關掉其他正在用鏡頭的程式；改用 `啟動` 腳本開 localhost。先用「載入照片測試」確認其他功能。 |
| 「掃描失敗／模型下載失敗」 | 檢查網路；或照「離線使用」準備；或到偵測設定改選 YOLOv10n。 |
| 掃描很慢（數秒） | 這台沒有 WebGPU：改 YOLOv10n、分塊改少一點、用「掃描一次」。Chrome／Edge 最新版通常自帶 WebGPU。 |
| 人數一直少很多 | 降低偵測門檻（0.15–0.2）、把鏡頭架高、請學生間隔站、最後用手動校正補點。 |
| 有多餘的點（把物品當人） | 手動點掉；它不會在重新掃描時回來。 |
| 圓點位置歪 | 重點四角（「重點四角」按鈕）；確認地板寬×深。 |
| 投影視窗沒更新 | 兩個視窗要是同一個網址來源（都用 `啟動` 腳本，或都用 file）。按一次主視窗任一按鈕。 |
| 換了網址／瀏覽器，班級不見了 | 資料綁定「瀏覽器＋網址」，請回原本的入口，或用「匯入備份」。網址加 `?fresh=1` 是測試模式：不讀也不寫儲存。 |

## 測試用網址參數

`index.html?img=照片網址&cal=0.18,0.7,0.86,0.7,0.92,0.92,0.06,0.92&q=3&fresh=1`
- `img`：載入照片取代鏡頭；`cal`：四角（左上、右上、右下、左下）的 0–1 比例座標；`q`：從第幾題開始；`fresh=1`：不讀暫存。

## 發布更新的注意事項

GitHub Pages 的 JS／CSS 會被瀏覽器快取約 10 分鐘。`index.html` 內每個 `<script>`／`<link>` 都帶有 `?v=日期` 版本參數；**每次發布更新請一併改掉這個值**（例如 `?v=20261110a`），避免老師看到新舊檔案混用而出錯。
